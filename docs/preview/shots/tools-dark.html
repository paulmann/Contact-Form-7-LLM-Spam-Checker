You are a strict anti-spam classifier for a website contact form.
You will receive ONE submission as a structured digest: form fields, client IP,
geo/ISP data (when known), user agent, referrer, page dwell time and rate-limit context.

Decide whether the submission is SPAM (unsolicited advertising, phishing, malware links,
SEO link dumps, gibberish/bot-generated text, fraudulent offers, credential harvesting,
irrelevant mass-mail content) or CLEAN (a plausible message written by a real human,
even if short, emotional, in any language, or containing 0-1 legitimate links).

Rules:
- Judge by the totality of evidence; a single weak signal is not enough for SPAM.
- Never mark a message SPAM only because of an unusual language or a free-mail domain.
- Technical payloads inside the message (SQL, HTML, scripts) always mean SPAM.

Respond with EXACTLY one word and nothing else: SPAM or CLEAN.

Each submission is appended as a structured digest: form fields, IP, country/ISP (when known), user agent, referrer, dwell time and the results of the local heuristics. The digest is capped at ~12 KB.

AbuseIPDB reputation check

Queries abuseipdb.com for the submitter IP: abuse confidence score, total community reports, country, ISP and Tor status. Results are cached locally to respect the daily API quota.

How the three thresholds work

A submission is flagged when ANY threshold is met: (1) abuse confidence score, (2) total community reports across all categories, (3) reports filed under the "Email Spam" category. Note: the API returns per-category data only for the most recent reports of an IP (verbose mode), so threshold 3 counts recent Email-Spam reports — a close approximation of the full category history. Set any threshold to 0 to disable it. IPs whitelisted upstream always pass.

Block from total reports ≥ …All categories combined. 0 disables this threshold. Example: 5 reports already indicates a repeat offender.
Block from "Email Spam" category reports ≥ …Counted from the most recent reports returned by the API (verbose mode). 0 disables this threshold. Example: 3 means an IP reported 3+ times specifically for e-mail/form spam gets blocked.

Pipeline order

How the checks combine per submission.

  1. Whitelist — whitelisted IPs bypass everything.
  2. Local heuristics — ban list, timing, honeypot, bot UA, rate limit, SQLi, XSS, links, keywords.
  3. AbuseIPDB — runs only while the submission is still clean (saves quota).
  4. LLM gateway — final AI verdict SPAM/CLEAN with geo context attached.
